## 2. Что строим

**ParkingScan** — система анализа парковки, состоящая из двух независимых модулей и общего API.

### Модуль A — Occupancy (занятость)

Вход: наклонный обзорный снимок парковки.
Выход: число машин, карта мест «занято / свободно», процент загрузки.

Ключевая особенность, отличающая проект от типовых решений: **парковочные места не размечаются вручную**. Сетка мест строится автоматически по нанесённой разметке, по одному снимку (раздел 7.2).

### Модуль B — ANPR (распознавание номеров)

Вход: видео, RTSP-поток или папка кадров с **наземной** камеры.
Выход: номера проехавших машин с привязкой ко времени, записанные в локальную БД.

### Связка

Модули соединяются на уровне БД: события въезда/выезда с номерами (модуль B) сопоставляются со снимками занятости (модуль A) по времени. Связка опциональна и реализуется последней.

## 3. Физическое ограничение, которое определяет архитектуру

**Номерные знаки не читаются с обзорных снимков парковки как система.** Это не ограничение модели, а геометрия съёмки.

Для надёжного распознавания требуется **около 100 пикселей на ширину номерного знака** (абсолютный минимум ~30 px в идеальных условиях). Номерной знак Армении имеет размер 520×110 мм. На обзорных снимках (GoPro с фишаем, под углом, раздел 1) около 100 px номер получает только у одной-двух машин прямо под камерой. В среднем поле ширина падает до десятков пикселей, в дальнем номер не разрешается вовсе. Кроме того, номер виден только у машин, повёрнутых к камере передом или задом; сильный наклон сжимает его по вертикали, соседние машины его перекрывают. Большинство машин площадки по такому снимку идентифицировать нельзя — читаемый номер на обзорном снимке случайность, а не режим работы.

**Следствие для архитектуры:** модуль ANPR работает с отдельного источника — камеры, установленной на въезде/выезде, смотрящей вдоль полосы движения. Это не компромисс, а стандартная схема промышленных парковочных систем: обзорная камера считает занятость, камера на шлагбауме читает номера.

**Требования к источнику для модуля B (записать в README как условие эксплуатации):**

- Ширина номера в кадре ≥ 100 px, минимально допустимо 40 px
- Выдержка 1/1000–1/2000 с при дневном свете для движущегося транспорта; 1/250–1/500 с ночью с ИК-подсветкой
- Камера направлена вдоль полосы, угол к плоскости номера по горизонтали ≤ 30°, по вертикали ≤ 30°
- Зона захвата 5–15 м

Если эти условия не выполнены, модуль запишет результат в таблицу невалидированных чтений и не будет выдавать номер как достоверный.

## 4. Честная формулировка требования «без ошибок»

Стопроцентная точность распознавания номеров недостижима ни одной существующей системой. Реалистичная цель, подтверждённая продакшн-замерами: **98–99% exact match** при соблюдении геометрии камеры из раздела 3.

Такая точность достигается не выбором «лучшей модели», а архитектурой пайплайна. Три приёма дают основной вклад:

1. **Множественные кадры на одну машину.** Пока машина проезжает зону захвата, снимается 15–20 кропов номера.
2. **Посимвольное голосование** по этим кропам.
3. **Валидация по формату страны** с позиционно-зависимой коррекцией.

**Явный антипаттерн: нейронный super-resolution кропов номера.** Производственное тестирование на 2000 размеченных кропах шириной менее 100 px показало: SRVGGNetCompact и Real-ESRGAN дают результат, идентичный отсутствию SR — 0.0% exact match, 0.4% посимвольной точности. Модели не восстанавливают символы, а **галлюцинируют правдоподобные, но неверные**, чем отравляют голосование. SR в проект не включать.

## 7. Модуль A — Occupancy

### 7.1 Детектор

`core/detector.py` — единственное место, где импортируется ultralytics и sahi.

Требования:

- Параметры читаются из `models/config.json`, **не хардкодятся**
- Модель загружается один раз при старте приложения, живёт в памяти и прогревается холостым прогоном до первого запроса
- Устройство выбирается автоматически: `cuda:0` если доступна, иначе `cpu`
- Входное изображение приводится к `TARGET_SIDE = 4000 * scale` по большей стороне, координаты боксов возвращаются в системе исходного изображения
- Инференс через `sahi.predict.get_sliced_prediction` с параметрами `slice_height=tile`, `slice_width=tile`, `overlap_*_ratio=overlap`, `perform_standard_pred=True` и постобработкой из конфига
- Порог уверенности внутри модели — 0.01, фильтр по рабочему порогу применяется после SAHI. Метрики ноутбука (mAP50, best_F1) и `vis_conf` измерены именно так: модель отдаёт кандидатов от 0.01, SAHI склеивает тайлы, затем результат отсекается по порогу. Поднимать порог модели до рабочего нельзя — для такой схемы заявленные метрики не измерялись
- Рабочий порог conf — обязательный параметр метода, скрытого значения по умолчанию в детекторе нет, порог задаёт приложение. Для сервиса это `default_conf` из `configs/default.yaml` (0.25): измерено на 35 снимках val-сплита как оптимальное для подсчёта (раздел 12, Этап 1). Параметр `conf` запроса его перекрывает. `vis_conf` остаётся в контракте модели как запись того, что нашёл ноутбук: он оптимален для F1 боксов, но недосчитывает машины
- Возвращается: массив боксов `xyxy` в float32, массив conf в float32

### 7.2 Калибровка — построение сетки мест по нанесённой разметке

**Условия съёмки, под которые рассчитан метод.** Снимки GoPro с фишаем, под углом, с руки или штанги (раздел 1). Масштаб машин внутри кадра меняется до 25 раз, линии изогнуты дисторсией, каждый снимок — отдельная площадка. Поэтому места строятся **по одному снимку**, по нанесённой разметке, в координатах кадра. Перспектива не выпрямляется: четырёхугольник между соседними разделителями уже является местом.

**Два режима.**

- *Разовый* — `POST /occupancy/detect` без `site_id`: сетка строится по тому же снимку, на котором считается занятость. Основной режим для имеющихся данных
- *Площадка* — `POST /sites/{site_id}/calibrate` сохраняет сетку, последующие снимки используют её. Корректно только при неподвижной камере; при несовпадении размера кадра с опорным — ошибка 409. Если передано несколько снимков с одной позиции, места объединяются по IoU четырёхугольников ≥ 0.5, `confidence` — доля снимков, на которых место найдено

**Алгоритм.**

1. **Детекция машин.** Детектор из 7.1 с порогом `default_conf`. Боксы нужны для модели масштаба, маски машин и подтверждения мест.
2. **Модель локального масштаба.** Робастная (Huber) регрессия логарифма короткой и длинной стороны бокса машины по координатам центра: `log w(x, y) = a + b·x + c·y`, так же для длинной стороны `L`. Логарифм — потому что размер машины внутри кадра меняется до 25 раз и линейная модель уходит в отрицательные значения. Предсказание ограничено наблюдаемым диапазоном размеров боксов: за краем облака машин экспонента уходит в тысячи пикселей. Все пороги ниже задаются в долях `w` или `L` в данной точке кадра, а не в пикселях. Если машин меньше `scale_min_cars` — берётся `slot_width_px` из запроса, иначе отказ с причиной `no_scale`.
3. **Рабочая зона** — пересечение: (а) ожидаемая ширина машины `w(x, y) ≥ roi_min_car_px` — дальнее поле, где разметка не читается, отсекается автоматически; (б) расстояние от центра кадра ≤ `roi_max_radius` полудиагонали — отсекается периферия фишая; (в) минус ручные полигоны исключения (рука, штанга, крепление). Ручной полигон включения, если задан, заменяет автоматическую зону. Зона сохраняется полигоном. Эта же зона — область, где разметке датасета можно верить (раздел 1).
4. **Маска краски.** Кадр уменьшается до `work_side` по большей стороне. Канал L из LAB, обработка полосами по масштабу: в каждой полосе white top-hat с ядром `tophat_kernel · w`. Порог локальный: среднее top-hat плюс `paint_sigma` стандартных отклонений в окне шириной в машину, но не ниже `paint_min_contrast`. Глобальный порог Оцу проверен и отвергнут — он пропускает текстуру плитки, листвы и асфальта, а локальный на пёстрой поверхности поднимается сам. Верхняя часть бокса машины, где кузов и крыша, расширенная на `car_mask_dilate`, исключается до порога — иначе крыши белых машин завышают порог и дают ложные линии. Нижняя полоса бокса высотой `car_mask_keep_bottom` не вырезается: разделители лежат у нижней кромки бокса, а низ машины обычно в тени и ярких откликов не даёт. Вырезание бокса целиком проверено и отвергнуто: в ближнем поле осевой бокс накрывает оба разделителя своего места, и ряд возле машины собрать не из чего. Краска белая (насыщенность HSV ≤ `paint_max_saturation`) или жёлтая по тону. Компоненты с шириной штриха по distance transform больше `max_stroke · w` отбрасываются: зебра, штриховка, стрелки, цифры.
5. **Сегменты.** `cv2.createLineSegmentDetector` на маске. LSD возвращает два сегмента на одну полосу краски, по её краям: пары почти параллельных (≤ `merge_angle_deg`), близких (≤ `merge_dist · w`) и перекрывающихся по длине сегментов склеиваются в осевую линию. Затем обрывки одной линии сшиваются: LSD рвёт разделитель на кривизне фишая, на неровном крае маски и на вырезах под машины. В сшивку идут только обрывки не короче `piece_min · L` — из россыпи мелких крох в текстуре она иначе собирает длинные ложные линии; сшиваются почти коллинеарные (≤ `link_angle_deg`) сегменты со смещением ≤ `merge_dist · w` и разрывом ≤ `link_gap · w`. Остаются сегменты длиной `[seg_len_min, seg_len_max] · L`.
**Гибрид разметки и машин (шаги 6–8).** На косом ракурсе разметка и машины дают разное: разделители видны там, где мест свободно, а в занятых участках их закрывают кузова. Поэтому обрывки разделителей задают направление и шаг ряда, а машины — его протяжённость там, где разметка закрыта. Чистая сборка по разметке проверена на Этапе 2b и отвергнута: recall по опорным точкам 0.06 на GOPR6537 и 0.14 на GOPR6757; гибрид даёт 0.50 и 0.43.

6. **Сборка ряда.** Граф: два разделителя соседние, если угол между ними ≤ `row_angle_deg`, шаг по нормали в `[gap_min, gap_max] · w` и сдвиг середин вдоль общего направления ≤ `row_shift · L`. Требование перекрытия отрезков на 50% проверено и отвергнуто: на косой парковке соседние разделители сдвинуты вдоль себя, и перекрытие падает до 0.1–0.2 при правильной паре. У каждого разделителя остаётся не больше одного ближайшего соседа с каждой стороны, связь только взаимная, ряд — цепочка. Цепочка принимается от `row_min_dividers` наблюдаемых разделителей (2): двух хватает, чтобы получить направление и шаг. Направление ряда — среднее направлений его разделителей. Шаг ряда измеряется в долях локальной ширины машины, а не в пикселях: для каждой пары соседей шаг по нормали делится на `w` в середине между ними, шаг ряда `step_w` — медиана этих отношений; в любой точке p шаг в пикселях равен `step_w · w(p)`, так перспектива учитывается сама. При трёх и более разделителях коэффициент вариации шага в долях `w` ≤ `row_gap_cv` — это отсекает зигзаги и случайные линии; у пары разделителей он не определён и не проверяется. Поэтому у цепочки ровно из двух наблюдаемых разделителей шаг принимается только в `[pair_gap_min, pair_gap_max] · w` (0.7–1.4), иначе цепочка отбрасывается: у пары нельзя отличить одно место от двух, а от трёх разделителей повторяемость шага сама говорит, что он настоящий. Места в ряду нумеруются слева направо, у вертикального ряда — сверху вниз.
7. **Заполнение и продолжение ряда по сетке.**
   - *Внутри наблюдаемого участка* — как раньше: промежуток в k шагов (k от 2 до `max_fill_gap`, отклонение от целого не больше 0.3 шага) заполняется k−1 разделителями линейной интерполяцией середин и направлений, `source = "interpolated"`; промежуток больше `max_fill_gap` шагов или не кратный шагу разрывает цепочку на отдельные ряды. Шаги сравниваются в долях `w`
   - *За крайними разделителями* ряд шагает наружу в обе стороны. Следующий разделитель ставится на расстоянии `step_w · w` от предыдущего вдоль оси ряда, с направлением ряда; ячейка — четырёхугольник между ними на передней и задней линиях (шаг 8). Ячейка принимается, если выполнено одно из двух: внутри неё лежит опорная точка машины (7.3), либо на её дальней границе есть наблюдаемый разделитель из шага 5, не вошедший в цепочку, — угол с направлением ряда ≤ `row_angle_deg`, смещение вдоль оси ряда не больше 0.3 шага, сдвиг вдоль направления разметки от середины ряда ≤ `row_shift · L`, иначе ход цепляется за разделитель соседнего ряда выше или ниже; тогда граница встаёт на этот разделитель
   - Если ячейка принята по машине, её центр подтягивается к опорной точке этой машины: дальняя граница сдвигается вдоль оси ряда так, чтобы проекция опорной точки легла посередине ячейки, но ширина ячейки остаётся в пределах 0.7–1.3 шага. Это гасит накопление ошибки на фишае и на искривлении ряда
   - Не принятая ячейка между двумя принятыми остаётся местом — это свободное место внутри занятого участка. Ход в сторону прекращается после `max_projected_run` (2) не принятых ячеек подряд, а также когда центр ячейки выходит за рабочую зону; не принятые ячейки на конце хода отбрасываются
   - Приёмка ряда — правило (а)/(б) ниже — проверяется после продолжения, по всем его ячейкам: ряд дотягивается до занятой части и находит там машину
   - Встречный ход: если разметка видна с двух концов ряда, а середина под машинами, две цепочки идут навстречу и дают дубли. После приёмки место, центр которого лежит в месте ряда с большим числом наблюдаемых разделителей, убирается

   Ряд принимается, если выполнено одно из двух: (а) опорная точка (7.3) хотя бы одной детекции машины лежит в одной из его ячеек; (б) ряд почти параллелен (≤ `row_angle_deg`) уже принятому ряду и отстоит от него не дальше `row_neighbour_gap · L`. Правило отсекает регулярные параллельные линии, между которыми не бывает машин: рамы стеклянных фасадов, ветки голого дерева. Условие (б) сохраняет полностью пустые ряды рядом с занятыми; принятие распространяется от ряда к ряду, пока добавляются новые.
8. **Места и источник.** Концы разделителей выравниваются по передней и задней линии ряда: полином по положению вдоль ряда (степень 2 при 5 и более разделителях, иначе 1) по концам наблюдаемых разделителей с одним проходом отсева выбросов, чтобы концы, частично закрытые машинами, не тянули линию. За пределами наблюдаемого участка линии продолжаются касательной в крайней точке, а не полиномом: парабола вне своих точек быстро уходит. Концы, лежащие у края кадра (ближе 1% большей стороны), — обрезанные кадром, а не концы разметки; в подгонку они не идут, а если настоящих концов на стороне меньше двух, линия идёт по крайнему наблюдаемому. Место — четырёхугольник из концов соседних разделителей на этих линиях. Проверки: выпуклость, площадь в `[slot_area_min, slot_area_max] · w²`. Источник места определяется качеством двух его границ, а не наличием машины: машина — разрешение ходу шагнуть дальше, а не свойство места.
   - `observed` — обе границы наблюдаемые, даже если машины в ячейке нет: это законное свободное место между двумя нарисованными линиями. Сюда же попадает ячейка хода, дальняя граница которой встала на наблюдаемый разделитель
   - `interpolated` — хотя бы одна граница восстановлена внутри наблюдаемого участка
   - `projected` — хотя бы одна граница спроецирована ходом шага 7 и в ячейке есть опорная точка машины
   - `extrapolated` — хотя бы одна граница спроецирована ходом и машины в ячейке нет
9. **Уверенность.** `observed` — 1.0, умноженная на видимую долю длины границ; `interpolated` — 0.6, если восстановлена одна граница, и 0.4, если обе; `projected` — 0.7; `extrapolated` — 0.4. `calibration_coverage` — доля подтверждённых мест: место подтверждено, если обе его границы наблюдаемые либо внутри него лежит опорная точка машины; `extrapolated` не подтверждено.
10. **Сохранение** в `data/sites/{site_id}.json`: размер опорного кадра, полигон рабочей зоны, использованные параметры, ряды с разделителями, места (`slot_id`, `row`, `index`, `polygon` из 4 точек, `confidence`, `source`: `observed` / `interpolated` / `projected` / `extrapolated` / `manual`, `confirmed`), `calibration_coverage`, `status`.

**Настраиваемые параметры** — `configs/default.yaml`, секция `calibration`.

- Шаги 1–5, подобраны на 4 снимках `data/samples/` на Этапе 2a: `work_side` 2000, `scale_min_cars` 5, `roi_min_car_px` 150, `roi_max_radius` 0.9, `tophat_kernel` 0.25, `paint_sigma` 2.0, `paint_min_contrast` 20, `paint_max_saturation` 60, `car_mask_dilate` 0.1, `car_mask_keep_bottom` 0.25 (добавлен на Этапе 2b), `max_stroke` 0.15, `merge_angle_deg` 3, `merge_dist` 0.08, `piece_min` 0.06, `link_angle_deg` 5, `link_gap` 0.5, `seg_len_min` 0.25, `seg_len_max` 2.0
- Шаги 6–10, Этап 2b: `row_angle_deg` 12, `gap_min` 0.5 (стартовое 0.7 отрезало настоящих соседей: на GOPR6537 шаг от 0.67 `w`), `gap_max` 2.5, `row_shift` 1.0, `row_min_dividers` 2 (вместо жёсткой тройки), `pair_gap_min` 0.7 и `pair_gap_max` 1.4 (шаг цепочки ровно из двух разделителей), `row_gap_cv` 0.35, `row_neighbour_gap` 2.5, `max_fill_gap` 3, `max_projected_run` 2 (значение 1 проверено и отвергнуто: на GOPR6537 recall падает с 0.50 до 0.28, а ряд, единственная машина которого стоит через одно свободное место от видимой разметки, не принимается целиком), `slot_area_min` 0.6, `slot_area_max` 3.0, `min_slots` 3
- Опорная точка машины — общий параметр `ground_offset` 0.15 (7.3)

Ручные полигоны зоны задаются для каждой площадки в её JSON.

**Деградация.**

- `calibration_coverage` — доля мест, у которых есть подтверждение: обе границы наблюдаемые либо внутри места лежит опорная точка машины. Доля одних `observed` не годится: гибрид по замыслу даёт в основном `projected`, статус всегда был бы `partial` и перестал бы нести информацию
- `status = "ok"` — не меньше `min_slots` мест и `calibration_coverage` ≥ 0.6
- `status = "partial"` — места есть, но покрытие ниже 0.6 (причина `low_coverage`) или мест меньше `min_slots` (причина `few_slots`); сетка используется, в ответе API флаг
- Статус оценивает только найденную сетку, а не долю площадки, которую она покрывает: `ok` при трёх местах из сорока — всё ещё `ok`. Полноту по занятым местам измеряет recall по регрессионному эталону
- `status = "failed"` с причиной `no_scale` / `no_markings` / `no_rows` — ответ 422; занятость для такого снимка считается в режиме «только счёт»: число машин в рабочей зоне, `occupancy_rate = null`
- Ручная правка через `PUT /sites/{id}/slots` — `source = "manual"`, `confidence = 1`, `status = "manual"`

**Известные ограничения, обязательно в README:** место без нанесённой разметки не обнаруживается; ряд должен иметь хотя бы два видимых разделителя, иначе его направление и шаг взять неоткуда; места под машинами восстанавливаются проекцией по шагу видимой части ряда, а не по собственной разметке; стёртая разметка, снег, мокрый асфальт с бликами и ночная съёмка не поддерживаются; дальнее поле вне рабочей зоны не анализируется.

**Сетка на косых снимках с руки строится частично.** На таком ракурсе разметка видна там, где мест свободно, а в занятых участках её закрывают кузова: у многих припаркованных машин эталона рядом нет ни одного сегмента разметки. Ряд, у которого не видно хотя бы двух разделителей, не находится, и его машины попадают в `unassigned`. На двух эталонных снимках место нашлось у 9 из 18 и у 3 из 7 припаркованных машин рабочей зоны.

**Критерий приёмки Этапа 2** (разбит на 2a и 2b, раздел 12):

1. Основной гейт — `test_calibration.py` на синтетическом кадре (раздел 13) и визуальная проверка заказчиком отрисовки мест и рабочей зоны на 4 снимках `data/samples/`
2. Регрессионный эталон `data/samples/slots_gt.json` на двух снимках с чёткой разметкой, GOPR6537 и GOPR6757: опорные точки припаркованных машин внутри рабочей зоны, полученные независимо от алгоритма 7.2 — по боксам детектора. Место считается найденным, если полигон, выданный алгоритмом, содержит эталонную опорную точку; IoU не используется, потому что осевые боксы с косыми местами не совпадают по форме даже при верном ответе. Так измеряется recall — доля припаркованных машин, у которых нашлось место. **Порог — достигнутые на приёмке цифры: recall не ниже 0.50 на GOPR6537 (9 из 18) и не ниже 0.43 на GOPR6757 (3 из 7).** Исходный порог 0.6 был назначен до работы с данными и снят: recall упирается не в сборку рядов, а в видимость разметки под машинами (см. «Известные ограничения»), и подгонять систему под число нечестно. Precision так не измерить — место без машины может быть законно свободным, — его заказчик проверяет глазами. Последующие изменения не должны ухудшать зафиксированный recall
3. Калибровка одного кадра 4000×3000 без учёта детектора — не больше 2 с на CPU

### 7.3 Определение занятости

`core/occupancy.py`.

- Занятость определяется по нижней части бокса — по точке касания земли, а не по IoS всего бокса. Причина — косой ракурс (раздел 1): кузов и крыша проецируются вверх по кадру, и бокс машины накрывает не только своё место, но и соседнее, лежащее выше
- Опорная точка детекции — середина нижней стороны бокса, поднятая на `ground_offset` высоты бокса (настраиваемый, стартовое значение 0.15), чтобы бампер не выносил точку за передний край места
- Место считается занятым, если внутри его полигона лежит опорная точка хотя бы одной детекции (`cv2.pointPolygonTest`)
- Одна детекция может быть назначена только одному месту: если опорная точка попала на стык полигонов, выбирается место, внутри которого она лежит глубже всего (наибольшее расстояние до границы)
- Если в одно место попали опорные точки двух детекций, место занято один раз, его `conf` — наибольшая из уверенностей
- Порядок проверок — сначала место, потом зона: точка внутри полигона места занимает его, даже если упрощённый контур рабочей зоны её срезал или ручное место нарисовано за пределами зоны. Детекции, не назначенные ни одному месту, делятся по зоне: внутри неё — `unassigned` (машины на проезде либо признак неполной калибровки), вне её — `outside_zone`, в занятость не входят
- `cars_in_zone` — число машин в рабочей зоне: назначенные местам плюс `unassigned`. При отказе калибровки с причиной `no_scale` модели масштаба нет, зоны тоже нет, зоной считается весь кадр, и `cars_in_zone` равен числу всех детекций. Это записано в описании поля в схеме API, чтобы потребитель не догадывался по `calibration_reason`
- Разовый режим: детектор запускается один раз на меньшем из двух порогов — `default_conf` и порога запроса; калибровка берёт боксы от `default_conf` (7.2, шаг 1), занятость — от порога запроса
- Режим площадки: берётся сохранённая сетка; площадки нет — 404, размер кадра не совпал с опорным — 409
- **Загрузка считается только по подтверждённым местам.** Место подтверждено, если оно подтверждено калибровкой (7.2: обе границы наблюдаемые либо при калибровке в нём стояла машина; ручное место подтверждено всегда) или занято на текущем снимке. Место `extrapolated` не подтверждено ничем — ни разметкой с двух сторон, ни машиной; если считать его свободным, оно раздувает число свободных мест и занижает загрузку. Поэтому:
  - `total_slots` — все места сетки, `confirmed_slots` + `unconfirmed_slots`
  - `occupied` — занятые места; занятое место подтверждено по определению
  - `free` — подтверждённые места без машины: `confirmed_slots − occupied`. Неподтверждённые места в `free` не входят
  - `occupancy_rate = occupied / confirmed_slots`. **К `total_slots` он не привязан**; если подтверждённых мест нет — `null`

**Выход.** В разовом режиме `site_id = null`. При `calibration_status = "failed"` ответ 200 в режиме «только счёт»: мест нет, `occupancy_rate = null`, отдаётся счёт машин в рабочей зоне `cars_in_zone` (7.2, «Деградация»). `calibration_reason` — причина статуса `partial` или `failed`, иначе `null`. `conf` места — уверенность детекции в занятом месте, у пустого `null`. `inference_ms` — детекция, калибровка и сопоставление вместе.

```json
    {"slot_id": "r0_s00", "occupied": true, "confirmed": true, "conf": 0.87, "source": "projected", "polygon": [[x,y],[x,y],[x,y],[x,y]]}
  ],
  "inference_ms": 1840
}
```

### 7.4 Отрисовка

`core/render.py` — вернуть изображение с наложением: занятые места красным, свободные зелёным, детекции без места (`unassigned`) жёлтым, контур рабочей зоны, в углу сводка. Неподтверждённые места рисуются тонким серым контуром без заливки: они не свободные и не занятые, зелёный цвет был бы той же неточностью, что и в числе свободных мест. Детекции вне зоны — тонкие серые рамки. В режиме «только счёт» мест нет: на картинке остаются зона, детекции и сводка с числом машин в зоне и причиной отказа калибровки. Кадр сначала уменьшается до `max_side` (по умолчанию 2000 px), потом на нём рисуется — толщина линий масштабируется от итогового размера. По умолчанию JPEG, PNG по параметру (раздел 10).

## 8. Модуль B — ANPR

Цель: максимальная достижимая точность. Порядок шагов важен, менять нельзя.

### 8.1 Пайплайн

```
источник (видео / RTSP / папка кадров)
   │
   ├─▶ 1. Детекция ТС      YOLO26 COCO, классы car/truck/bus/motorcycle
   │
   ├─▶ 2. Трекинг          BoT-SORT → стабильный track_id на каждую машину
   │
   ├─▶ 3. Детекция номера  внутри бокса ТС, yolo-v9-s-608-license-plate-end2end
   │
   ├─▶ 4. Оценка качества  скор кропа, накопление top-K лучших на трек
   │
   ├─▶ 5. Ректификация     перспективная коррекция кропа
   │
   ├─▶ 6. OCR              cct-s-v2-global-model на каждом из K кропов
   │
   ├─▶ 7. Голосование      посимвольное, взвешенное по качеству
   │
   ├─▶ 8. Валидация        формат Армении + позиционная коррекция
   │
   └─▶ 9. Запись в БД      достоверные → vehicles, сомнительные → unverified
```

### 8.2 Шаг 4 — оценка качества кропа (`best_shot.py`)

Для каждого кропа номера считается скор как взвешенная сумма четырёх нормированных метрик:

| Метрика | Как считать | Вес |
|---|---|---|
| Размер | ширина кропа в px, нормируется на 100 px с отсечкой на 1.0 | 0.40 |
| Резкость | дисперсия лапласиана `cv2.Laplacian(gray, cv2.CV_64F).var()`, нормируется на скользящий максимум по треку | 0.30 |
| Уверенность детектора | conf детектора номера | 0.15 |
| Фронтальность | `1 - abs(aspect / 4.73 - 1)`, где 4.73 = 520/110, эталонное отношение сторон номера Армении | 0.15 |

На каждый `track_id` в памяти держится очередь с приоритетом на **K = 20** кропов с максимальным скором. Кропы с шириной менее 40 px отбрасываются сразу.

Трек закрывается, когда машина не детектировалась 15 кадров подряд либо покинула кадр. После закрытия запускаются шаги 5–9.

### 8.3 Шаг 5 — ректификация (`rectify.py`)

Детектор номера возвращает прямоугольник, выровненный по осям, — этого недостаточно, номер в кадре повёрнут и наклонён.

Порядок:

1. Расширить бокс на 10% с каждой стороны
2. Перевести в оттенки серого, применить адаптивную бинаризацию
3. Найти внешний контур, применить `cv2.minAreaRect`
4. Если площадь минимального прямоугольника составляет 0.6–1.0 от площади бокса — взять его четыре угла; иначе откатиться на углы исходного бокса
5. `cv2.getPerspectiveTransform` → `cv2.warpPerspective` в фиксированный размер 192×48 (соотношение близко к 4.73)

Без ректификации точность OCR на наклонных кадрах падает существенно. Шаг обязателен.

### 8.4 Шаг 7 — посимвольное голосование (`voting.py`)

Именно этот шаг даёт основной прирост точности.

1. Прогнать OCR по всем K ректифицированным кропам. Получить K строк с посимвольными вероятностями
2. Отбросить строки, длина которых отличается от моды длин по треку
3. Для каждой позиции символа построить взвешенную сумму вероятностей: вес = скор качества кропа из шага 4
4. Итоговый символ = argmax по позиции. Итоговая уверенность строки = среднее геометрическое уверенностей по позициям
5. Записать в БД все K сырых чтений в таблицу `plate_reads` для аудита, а результат голосования — в `vehicles`

### 8.5 Шаг 8 — валидация формата (`validators.py`)

**Формат номеров Армении:**

- Размер знака: 520×110 мм, чёрные символы на белом фоне
- Частные ТС: `NN LL NNN` — две цифры, две латинские буквы, три цифры
- Государственные ТС: `NNN LL NN` — три цифры, две буквы, две цифры
- Разрешены все 26 латинских букв A–Z. До 2010 использовались только четыре буквы армянского происхождения, с 2019 алфавит открыт полностью
- С 6 августа 2014 действует дизайн с флагом, голограммой и Data Matrix
- Существует двухрядный вариант — первая группа цифр и буквы сверху, остальные цифры снизу

Регулярные выражения:

```
частные:          ^\d{2}[A-Z]{2}\d{3}$
государственные:  ^\d{3}[A-Z]{2}\d{2}$
```

**Позиционная коррекция.** OCR систематически путает визуально близкие символы. Коррекция применяется с учётом того, цифровая позиция или буквенная:

| В цифровой позиции | Заменить на |
|---|---|
| O, Q, D | 0 |
| I, L | 1 |
| Z | 2 |
| S | 5 |
| B | 8 |
| G | 6 |

| В буквенной позиции | Заменить на |
|---|---|
| 0 | O |
| 1 | I |
| 8 | B |
| 5 | S |
| 2 | Z |
| 6 | G |

Порядок: сначала проверить строку на соответствие одному из двух шаблонов «как есть». Если не совпало — применить коррекцию под каждый шаблон и проверить снова. Если совпало ровно с одним — принять. Если ни с одним или с обоими неоднозначно — пометить как невалидированное.

Формат должен задаваться в конфиге, чтобы систему можно было переключить на другую страну без правки кода.

### 8.6 Шаг 9 — критерии записи

Запись в `vehicles` как достоверная, если одновременно:

- Уверенность после голосования ≥ 0.80
- Строка прошла валидацию формата
- Проголосовало не менее 5 кропов

Иначе — запись в `unverified` вместе с лучшим кропом на диск, для ручной проверки.

### 8.7 Что не делать

- **Не использовать нейронный super-resolution.** Обоснование в разделе 4
- Не запускать OCR на каждом кадре — только на отобранных K кропах после закрытия трека. Иначе GPU уходит в простой на бесполезной работе
- Не полагаться на одиночное чтение, даже с высокой уверенностью

## 9. База данных

SQLite, файл `data/parkingscan.db`. Режим WAL для конкурентного чтения во время записи.

```sql
# площадки
sites(
  site_id TEXT PRIMARY KEY,
  name TEXT,
  ref_width INTEGER,
  ref_height INTEGER,

  snapshot_id INTEGER REFERENCES snapshots,
  row_idx INTEGER,
  slot_idx INTEGER,
  polygon TEXT,
  confidence REAL,
  # observed / interpolated / projected / extrapolated / manual
  source TEXT
)

# снимки занятости; в разовом режиме site_id = NULL, при failed-калибровке occupancy_rate = NULL
snapshots(
  id INTEGER PRIMARY KEY,

)

# состояние каждого места на снимке
slot_states(
  snapshot_id INTEGER REFERENCES snapshots,

  conf REAL,
  PRIMARY KEY (snapshot_id, slot_id)
)

# машины с распознанными номерами
vehicles(
  id INTEGER PRIMARY KEY,
  track_id INTEGER,
  source TEXT,
  first_seen TIMESTAMP,
  last_seen TIMESTAMP,
  vehicle_class TEXT,
  plate TEXT,
  plate_conf REAL,
  votes_count INTEGER,
  validated INTEGER,

)

# сырые чтения для аудита

)
```

## 10. API

FastAPI. Модели загружаются в `lifespan`, а не при каждом запросе.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Статус, загружены ли модели, устройство, версия |
| GET | `/metrics` | Счётчики запросов, средняя латентность, uptime |
| POST | `/occupancy/detect` | Фото + необязательный `site_id` → JSON из раздела 7.3. Без `site_id` сетка строится по этому же снимку (разовый режим из 7.2) |
| POST | `/occupancy/render` | То же, но ответ — изображение: по умолчанию JPEG не больше 2000 px по большей стороне. Параметры `format` (`jpeg` / `png`) и `max_side` |
| POST | `/occupancy/batch` | Папка или архив → CSV со сводкой. Без `site_id` каждый снимок обрабатывается в разовом режиме, с `site_id` — по сохранённой сетке |
| POST | `/sites/{site_id}/calibrate` | Один или несколько снимков с одной позиции камеры → сетка мест по разметке (7.2) |
| GET | `/sites/{site_id}/slots` | Текущая сетка |
| PUT | `/sites/{site_id}/slots` | Ручная правка сетки |
| POST | `/anpr/run` | Запустить обработку видео или RTSP, вернуть `job_id` |
| GET | `/anpr/jobs/{job_id}` | Статус обработки |
| GET | `/anpr/vehicles` | Список распознанных номеров, фильтры по времени и validated |
| GET | `/anpr/unverified` | Сомнительные чтения с путями к кропам |

Правила:

- Все ответы — типизированные pydantic-модели из `api/schemas.py`
- Ошибки возвращают структурированный JSON с полями `error`, `detail`
- Длительные операции (`/anpr/run`, `/occupancy/batch`) выполняются в фоне через `BackgroundTasks`, клиенту сразу возвращается `job_id`. `/sites/*/calibrate` синхронный: один кадр калибруется за 1–2 с, а клиенту сразу нужны статус и причина отказа, для которых у площадок нет эндпоинта статуса задачи
- Размер загружаемого файла ограничен, значение в конфиге

## 11. Стиль кода — обязательно к соблюдению

Требования заказчика, отступать нельзя:

- **Комментарии только одного вида: строка, начинающаяся с `#`, расположенная над кодом.** Никаких комментариев в конце строки, никаких docstring в тройных кавычках, никаких блочных комментариев
- Символ `#` используется для комментариев во всех файлах проекта без исключений, включая YAML, Dockerfile, `.env`
- Код должен быть чистым и хорошо задокументированным — документирование ведётся комментариями указанного вида и понятными именами
- Не использовать устаревшие библиотеки и устаревшие API. При сомнении в актуальности API — свериться с текущей документацией библиотеки перед написанием кода
- Типизация обязательна: аннотации типов у всех публичных функций и методов
- Никаких «заглушек на будущее», закомментированного кода и TODO-мусора в финальной версии

Пример требуемого оформления:

```python
# приводим изображение к масштабу, на котором обучалась модель
def to_model_scale(image: np.ndarray, target_side: int) -> tuple[np.ndarray, float]:
    # коэффициент приведения по большей стороне
    k = target_side / max(image.shape[:2])
    # уменьшение делаем area-интерполяцией, увеличение - кубической
    interp = cv2.INTER_AREA if k < 1 else cv2.INTER_CUBIC
    resized = cv2.resize(image, None, fx=k, fy=k, interpolation=interp)
    return resized, k
```

Причина: после Этапа 3 проект работает, но запустить его может только автор; Docker и README делают его показываемым, а база ничего не чинит и добавляется потом без переделок. - `POST /occupancy/render`

**Критерий:** на 35 снимках val-сплита ноутбука (`tests/check_detector.py <папка датасета>`) при пороге подсчёта 0.25 медиана абсолютного отклонения числа машин по снимкам ≤ 10% и F1 боксов при IoU 0.5 ≥ 0.83. - Сервис в контейнере работает от непривилегированного пользователя `parkingscan` (uid 1000); каталог `/app/data` принадлежит ему, запись проверена с bind-томом, с именованным томом и без тома

- `test_validators.py` — параметризованные случаи: валидные номера обоих форматов, номера с типовыми ошибками OCR, заведомо мусорные строки
- `test_voting.py` — синтетические наборы чтений: единогласное, с одним расхождением, с расхождением в весах; проверка, что вес качества влияет на исход
- `test_calibration.py` — синтетический кадр: ряды белых разделителей в перспективе на сером фоне с шумом, зебра и прямоугольники-«машины» поверх части разделителей; проверка, что восстанавливается ожидаемое число мест, зебра не даёт ни одного места, перекрытые разделители восстановлены интерполяцией, а регулярные тонкие линии без машин вдали от ряда (модель фасада) рядом не становятся. Пустой кадр даёт `status = "failed"` с причиной `no_scale`, кадр с машинами без разметки — `no_markings`, оба без исключения
- `test_occupancy.py` — заданные полигоны и боксы; проверка опорной точки (середина нижней стороны бокса, поднятая на `ground_offset`), назначения каждой детекции не более чем одному месту — на стыке полигонов выигрывает место, внутри которого точка глубже, — и разнесения неназначенных детекций в `unassigned` и `outside_zone`
- `test_detector.py` — проверка приведения масштаба и обратного пересчёта координат
- `test_api.py` — `/health`, `/occupancy/detect` на маленьком изображении через `TestClient`

Тесты не должны требовать GPU и не должны скачивать модели из сети — модели мокаются.
